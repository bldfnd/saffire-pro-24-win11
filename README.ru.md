Возвращает к жизни Focusrite **Saffire Pro 24** (FireWire) на Windows 11
**24H2 / 25H2** после изменения **Windows Driver Policy** в апреле 2026 —
**без** тестового режима подписи и **без** переподписи драйверов.

## Предыстория

Раньше Windows доверяла драйверам ядра, подписанным по старой программе
*cross-signed*. С обновлением за апрель 2026 Microsoft убрала это доверие для
Windows 11 24H2/25H2/26H1 и Windows Server 2025. Ограничение реализовано политикой
Code Integrity:

| ID политики | Назначение |
|---|---|
| `{784C4414-79F4-4C32-A6A5-F0FB42A51D0D}` | «Microsoft Windows Cross Certificates for Code Integrity Exceptions **Audit** Policy» |
| `{8F9CB695-5D48-48D6-A329-7202B44607E3}` | «Microsoft Windows Cross Certificates for Code Integrity Exceptions **Policy**» (принудительная) |

Принудительная политика блокирует последний драйвер Saffire — **4.3.0.41017**
(2015 год, подпись `TC Applied Technologies`, SHA-1) — событиями Code Integrity
**3077**.

Microsoft описывает, как эту политику отключить (раздел *«How do I turn off the
Windows Driver Policy?»* в статье поддержки «The Windows Driver Policy»). Этот проект
автоматизирует процесс, потому что документированная команда `CiTool` на некоторых
сборках отклоняется с ошибкой `0x80070005` — тогда файл политики приходится удалять
с EFI-раздела вручную.

Когда политики нет, Windows снова доверяет старым cross-signed сертификатам, и
**оригинальный** драйвер Focusrite загружается нормально.

## Что это даёт

- `testsigning` остаётся **выключенным** → Secure Boot может быть **включён**,
  ядерные анти-читы работают, надписи «Тестовый режим» нет.
- **Никакой переподписи** и самодельных сертификатов — используется драйвер вендора
  как есть.
- Работает и для других старых cross-signed драйверов (M-Audio, Line 6, X-Rite и
  т.п.) — скрипты универсальные.

## Требования

- Windows 11 24H2 / 25H2 (build 26100+) с обновлением апреля 2026 или новее.
- Оригинальный пакет драйвера Focusrite. **В репозитории его нет** (авторские права).
  Скачайте с официальной страницы загрузок Saffire (`Saffire MixControl 3.7`,
  драйвер 4.3.0.41017) и положите в `drivers\` файлы:
  `Saffire.inf`, `Saffire.sys`, `SaffireAudio.sys`, `SaffireMidi.sys`, `Saffire.cat`.
  Они же лежат в `C:\Program Files\Focusrite\Saffire MixControl\` после установки
  MixControl.
- Права администратора.

## Быстрый старт

```powershell
# 1. положить файлы драйвера в .\drivers\  (см. выше)

# 2. убрать блокирующую политику
powershell -ExecutionPolicy Bypass -File .\fix-policy.ps1

# 3. поставить драйвер вендора
powershell -ExecutionPolicy Bypass -File .\install.ps1

# 4. перезагрузиться
```

Проверка после перезагрузки:

```powershell
powershell -ExecutionPolicy Bypass -File .\verify.ps1
```

Ожидаемо: службы `Saffire`, `SaffireAudio`, `SaffireMidi` — Running, все узлы
устройств Saffire — `OK`, а в журнале
`Applications and Services Logs → Microsoft → Windows → CodeIntegrity → Operational`
только события **3076** (аудит).

## Откат

Перед удалением файл политики сохраняется в `.\backup\`. Чтобы вернуть защиту:

```powershell
# Secure Boot при необходимости выключить, затем:
mountvol S: /s
copy .\backup\esp_{8F9CB695-*.CIP} "S:\EFI\Microsoft\Boot\CiPolicies\Active\{8F9CB695-5D48-48D6-A329-7202B44607E3}.cip"
mountvol S: /d
# перезагрузка
```

Кумулятивное обновление Windows тоже может вернуть политику само по себе.

## Проверено на

- Windows 11 Pro 25H2, build 26200.9974, x64
- Gigabyte Z590 AORUS MASTER, Intel i9-10850K
- Контроллер FireWire VIA VT6315N OHCI (`PCI\VEN_1106&DEV_3403`)
- Saffire Pro 24 (`1394\FOCUSRITE&SAFFIRE_PRO_24\…`), MixControl 3.7 / 3.8b1
- Пакет драйвера 4.3.0.41017 (`Saffire.inf`)

## ⚠️ Предупреждение о безопасности

Удаление политики возвращает доверие **всей** устаревшей cross-signed программе,
включая старые драйверы с известными уязвимостями. Microsoft убрала это доверие
намеренно. Делайте так только если железо действительно нужно, держите систему
обновлённой, а если перестали пользоваться устройством — верните политику.

## Известные нюансы

- Установщик MixControl от Focusrite удаляет уже установленный пакет драйвера
  (а в тихом режиме не ставит обратно). После него запустите `install.ps1` снова.
- Крупные обновления Windows могут вернуть политику → запустите
  `fix-policy.ps1` и перезагрузитесь.
- События **3076** для этих драйверов — норма (режим аудита), **3077** означает,
  что политика снова активна.

## Резервный путь: тестовый режим

Если в будущих сборках драйвер откажется загружаться даже без политики, остаётся
тестовый режим (`bcdedit /set testsigning on`) плюс локальная переподпись драйвера
самоподписанным сертификатом. Это ломает доверие Secure Boot и ядерные анти-читы,
поэтому используется как крайняя мера — здесь не реализовано.
